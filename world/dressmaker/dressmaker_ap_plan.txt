RESEARCH FINDINGS (from ILSpy)
-------------------------------
- Campaign: GameManager.Instance.ActiveCampaign (CampaignDefinition,
  a plain ScriptableObject - no static "all campaigns" list)
    .quests     = story commissions
    .sideQuests = pigeon commissions
    VERIFIED: 53 story + 24 side + FinalQuest = 78 commissions
    .pigeonUnlockRequirement / .giftingUnlockRequirement /
    .nonCommissionRequirement = QuestOutcomeRequirement (logic gates)
- QuestDefinition is a ScriptableEnum:
    - QuestDefinition.AllQuestDefinitions = every quest (96 total,
      incl. junk: ExampleQuest, RepeatingQuest, Quest0?, *Demo)
    - .name = stable internal id (use for AP ids)
    - .PrettyNameUnlocalizedEnglishDefault = display name
    - .questGiverCharacter, .budget
    - .requirements (StoryletRequirement) = what unlocks the quest
    - .completionRequirements (QuestRequirement) = what finishes it;
      some are FabricCompositionRequirement / FabricTypeRequirement
      -> commission logic must require those fabric ITEMS
    - QuestOutcome enum: NotCompleted, Failed, Succeeded, Excelled
- Other static lists: FabricType.AllFabricTypes,
  CharacterDefinition.AllCharacterDefinitions
- Each character has a gift quest (CharacterDefinition.giftQuest,
  QuestDefinition.IsGiftQuest())
- TODO: are gift quests part of the 78? What's QuestOutcomeRequirement?
- Adora = the princess (PrincessGiftQuest is hers). 10 characters.
- Patterns = GarmentComponent (ScriptableEnum, looked up by name).
  Unlocked set = PlayerProgress.Current.unlockedPatterns.
  Public static UnlockPattern(string patternName) [YarnCommand
  "unlock_pattern"] adds one + shows a notification -> mod can use
  it to grant received pattern items. Callers may be in Yarn
  dialogue files (not visible in ILSpy "Used By").
- Relationship = float per character in
  PlayerProgress.characterRelationships; level = floor, clamp 0-5.
  Changed via PlayerProgress.ModifyCharacterRelationship(char, delta).
- Patterns natively unlock only from friendship levels (per user;
  Yarn dialogue unverified).
- Fabrics are bought in a shop. DECIDED: AP fabric item = unlocks
  that fabric in the shop ONLY (still costs gold, nothing given).

MORE DECISIONS
---------------
- FRESH SAVE REQUIRED for AP play.
- Starting patterns: random, set by apworld options (defaults
  6 bodices / 6 skirts / 4 sleeves / 2 collars), given as starting
  items. Mod removes the game's native starter patterns on a fresh
  save. TODO: dump a new save's unlockedPatterns to see natives;
  check whether the tutorial quest needs a specific pattern.
- Commission check = dress ACCEPTED (any outcome). Failed dresses
  get redone, so nothing is missable.
- Reputation comes from every finished dress (commission, gift,
  rack sale) -> reputation checks need ~no logic.
- Characters unlock through story as you meet them (relationship
  logic depends on story progress - work out in Phase 4).
- Gift quests are NOT commissions (they enable gifting).
- Filler: gold, reputation boosts.
- commissions_in_pool: recommended DROP (all 78 = checks).
- Mod sends checks by location NAME (MultiClient.Net can look up
  ids by name) -> decide naming format before Phase 5.
- Relationship hook: one Prefix on ApplyPatternsForRelationship
  Level -> send check (character + level) AND return false to skip
  the native pattern unlock.

RELATIONSHIPS (from gameplay)
------------------------------
- Raised by commissions AND gifts. A gift = a dress you make.
- Gifting is unlimited; unlocked after a few commissions
  (CampaignDefinition.giftingUnlockRequirement).
- A gift matching all the recipient's likes = a full level.
- Each level natively unlocks 1-3 patterns (to be replaced by AP).
- Logic: level N of character C = C unlocked + gifting unlocked.
- Later logic problem: commissions need tag scores/colors from
  pattern+fabric combos (TagScoreRequirement etc). Dump each
